# Phase 6.2 — DECterm runtime font-selection path

Updated: 2026-10-21

> **Phase 6.3 correction:** this document preserves the Phase 6.2 server-specific findings, but its ranking of 75dpi/14pt as the KEK runtime-default candidate is superseded. DECstation 5000/125 + VRT19 existed with both PX and PXG graphics, and the KEK graphics/X-server branch is not identified. See `PHASE6_3_GRAPHICS_SERVER_BRANCH.md`.

## Conclusion

The project now separates two questions that were previously conflated:

1. **Which DEC Terminal glyph raster has been verified from real ULTRIX 4.3 media?**
2. **Which font-density path would an ordinary DECstation 5000/125 `Xws` session select by default?**

The answers are not the same evidence item.

### Documented Xws default path

For `Xws`, ULTRIX/UWS documentation identifies **75 dpi** as the normal/default
font-density path.  To run `Xws` with the 100-dpi font path, the documented
procedure is to add the server options:

```
-fd 100 -dpi 100
```

to the X server startup entry (for example in `/etc/ttys`) and restart the
server.

DECterm/dxterm documentation says the default `fontSetSelection` is the
**Little Font**.  The Little Font is:

- 75-dpi server path: **14 point**
- 100-dpi server path: **10 point**

Within the **Xws branch**, the corresponding default target is:

`-DEC-Terminal-Medium-R-Normal--14-140-75-75-C-80-ISO8859-1`

Phase 6.3 shows that this cannot be promoted to a machine-wide KEK default
until the graphics/X-server branch is identified.

### Media-confirmed 100dpi raster

The supplied ULTRIX 4.3 RISC medium directly confirms `UDWFONT15430` /
`terminal10.pcf`:

`-DEC-Terminal-Medium-R-Normal--14-100-100-100-C-80-ISO8859-1`

with a full 8×15 cell, ascent 12, descent 3, advance 8, and 195 glyphs.
This remains the project's strongest **media-side glyph reference**, but its
runtime use on `Xws` requires a 100-dpi server selection that has not yet been
shown for the KEK machine.

### Why the public GitHub Pages raster remains valid

The separately licensed public `term14.bdf` has the exact 75dpi/14pt metadata
expected by the documented Xws default path.  Independently, its normalized
8×15 glyph rasters have already been compared against the ULTRIX 100dpi
`terminal10` artifact:

- complete set: **195/195 identical**
- ASCII 32–126: **95/95 identical**

So the new runtime-selection finding changes the **provenance ranking**, not the
visible bitmap currently rendered by the public reconstruction.

## ULTRIX subset evidence

The ULTRIX 4.3 installation material distinguishes:

- `UDWFONT430`: 75-dpi X11/DECwindows fonts; required baseline for worksystems
- `UDWFONT15430`: 100-dpi X11/DECwindows fonts; additional high-density font set

This is consistent with the documented `Xws` 75-dpi default and explicit
100-dpi override.

## Remaining media-side check

The final missing proof is to directly extract the ULTRIX 4.3
`UDWFONT430/terminal14.pcf` from the same supplied installation medium and
compare it with:

1. the bundled public X Consortium `term14.bdf`; and
2. the already extracted ULTRIX `UDWFONT15430/terminal10.pcf`.

`tools/extract_ultrix_dec_terminal_density_pair.py` now performs that extraction
and three-way normalized-raster comparison in one run.  The original ISO is
never included in the project or output package.

## Evidence boundary

Still unknown for KEK on 1992-09-30:

- exact `/etc/ttys` X server command line;
- whether `-fd 100 -dpi 100` was set;
- user/session `.Xdefaults` or resource database;
- whether DECterm was actually the local terminal emulator used for the LMB;
- exact graphics option and monitor pairing of the surviving DECstation.

The physical VRT19-class density of roughly 95 dpi is therefore **not sufficient
by itself** to promote the 100-dpi font path to the runtime default.
